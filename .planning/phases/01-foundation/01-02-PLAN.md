<objective>
Implement context extraction and type resolution infrastructure.

This plan builds the AST-based context assembler (context_assembler.py) that extracts function signatures, struct definitions, typedefs, macros, and HAL functions from C diffs using tree-sitter. Also builds the type resolver (type_resolver.py) that maps C types to CType enum, resolves typedef chains, classifies parameters, and determines correct zero/null values. Both modules are independent of Plan 01-01 and can be built in parallel, though they work together in the full pipeline.

Purpose: Extract structured context from C diffs using robust AST parsing (not fragile regex). Provide deterministic type classification that the LLM pipeline and Jinja2 templates both depend on.

Output: src/context_assembler.py (ContextAssembler class), src/type_resolver.py (TypeResolver class), tests for both modules.
</objective>

- Dataclass pattern for complex return types (FunctionSignature, StructDefinition, ContextPackage, TypeMetadata)

# Key Research from RESEARCH.md

- HAL function detection: look for calls with HAL_/Rte_/Com_ prefixes in AST
- Zero values differ by type: 0u for uint, 0.0f for float, FALSE for bool, NULL_PTR for pointers, "" for structs/arrays
- Null values only apply to pointer types: NULL_PTR
- ParamClass classification: scalar, struct, pointer, array, float, bool
- Recursive typedef resolution: MyType → uint8 → UINT8 with loop detection

4. Define ContextPackage dataclass with fields:
   - diff_text: str
   - function_signatures: Dict[str, FunctionSignature]
   - struct_definitions: Dict[str, StructDefinition]
   - typedef_map: Dict[str, str]  # alias → base type
   - macro_constants: Dict[str, str]  # name → value
   - hal_functions: Set[str]  # function names needing stubs

5. Define ContextAssembler class:
   - HAL_PREFIXES = {'HAL_', 'Rte_', 'Com_'} (class attribute)
   - __init__(self): initialize tree-sitter parser for C (self.language, self.parser)

6. assemble(self, diff_text: str) -> ContextPackage:
   - Parse diff_text with tree-sitter
   - Call _extract_functions(tree), _extract_structs(tree), _extract_typedefs(tree), _extract_macros(tree), _detect_hal_functions(tree)
   - Return ContextPackage with all extracted data

7. _extract_functions(self, tree) -> Dict[str, FunctionSignature]:
   - Use tree-sitter query to find function_definition nodes
   - Query: (function_definition type: (type_identifier) @return_type declarator: (function_declarator declarator: (identifier) @name parameters: (parameter_list ...) @params) @func
   - Process captures to build FunctionSignature objects
   - Return dict mapping function_name → FunctionSignature

8. _extract_structs(self, tree) -> Dict[str, StructDefinition]:
   - Use tree-sitter query to find struct_specifier nodes
   - Query: (struct_specifier name: (type_identifier) @name body: (field_declaration_list (field_declaration type: (type_identifier) @field_type declarator: (field_identifier) @field_name)*) @struct)
   - Process captures to build StructDefinition objects with field dicts
   - Return dict mapping struct_name → StructDefinition

9. _extract_typedefs(self, tree) -> Dict[str, str]:
   - Use tree-sitter query to find type_definition nodes
   - Query: (type_definition type: (type_identifier) @alias declarator: (type_identifier) @base_type)
   - Process captures to build alias → base_type mapping
   - Return dict

10. _extract_macros(self, tree) -> Dict[str, str]:
    - tree-sitter doesn't parse preprocessor well, use regex fallback
    - Pattern: r'^#define\s+(\w+)\s+(.+)$' with MULTILINE flag
    - Iterate matches, build name → value dict
    - Return dict

11. _detect_hal_functions(self, tree) -> Set[str]:
    - Use tree-sitter query to find call_expression nodes
    - Query: (call_expression function: (identifier) @func_name)
    - Process captures, filter by HAL_PREFIXES
    - Return set of HAL function names

Do NOT reuse legacy signature_extractor.py — this is a fresh implementation per decision D-01.
